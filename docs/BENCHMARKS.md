# Benchmarks

The benchmark family lives in `src/field_engine/bench/`. One driver (`faltbench_v1.py`) runs each
component (`_komp_*.py`) in its own subprocess, aggregates the part files into one result JSON,
appends one row to a trend file and applies a gate whose thresholds (`THRESH`) are pre-registered
and whose baseline is written only by `--rebaseline --reason "..."`.

```
python src/field_engine/bench/faltbench_v1.py --alla            every component, declared sizes
python src/field_engine/bench/faltbench_v1.py --rok             reduced sizes, smoke round
python src/field_engine/bench/faltbench_v1.py --ingen-korning   aggregate + gate existing parts
python src/field_engine/bench/faltbench_v1.py --bara faltkarna,ikarus
pytest tests/test_bench.py                                      wrappers; 10 passed on a device
```

Every part is generated by this repository: the analytic test field (box minus a through cylinder),
an analytic sphere, closed analytic bodies (box, rotated box, cylinder, rotated cylinder, sphere),
the holed plate from `examples/parts/holed_plate_v1.py` (through holes of radius 1, 2, 4, 8, 16 mm
in one plate) and the recipe bracket from `examples/parts/bracket_part_v1.py`.

Machine for the rows marked `CPU backend`: Warp CPU device, no CUDA device present (the driver
reports CUDA error 804 and falls back), `nice -n 15`, `OMP_NUM_THREADS=4`, run 2026-09-12.
Machine for the rows marked `RTX 5070`: same host, NVIDIA GeForce RTX 5070 (12 GB, sm_120), Warp
1.17.0, CUDA Toolkit 12.9, driver 13.0, `nice -n 15`, `OMP_NUM_THREADS=4`, run 2026-09-12, nothing
else on the device. Every device row was measured twice (run 1 / run 2 below); the quantities the
benchmark declares deterministic (the sha over the field, the voxel volumes, the active-block
counts) are bit-identical between the two runs, latencies are not claimed deterministic and vary.
No number is carried over from another machine.

Size L of this op is the plate at 0.5 mm, which is 461 397 cells, not the 26 M the source comment in
`_komp_mesh_sdf.py` claims; the grid is 249x109x17 because the plate is thin. It is still the largest
declared size and it is the size that was device-gated. 99.4 % of its time is the CPU stage (raster,
flood, EDT), so the op does not become device-bound at this size: the device only helps the classify
step, which is 1.05 ms of 261 ms.
